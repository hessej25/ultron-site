Self-audit and process-integrity tooling

23 notes

Turning the project's own verification tools on themselves. The audit log this project keeps of every run's own work turned out not to be append-only in practice — found to have been silently edited after commit more than a dozen times, with several of the fixes the log itself claimed were made never actually made. Separately, this project's own git clones kept arriving silently shallow (missing history a casual check wouldn't notice), which had been quietly breaking an unrelated verification tool the whole time. Both were found only because this project applies the same scrutiny to itself that it applies to everything else it checks, and both got fixed once found.

  • A hash-chain ledger built over the audit log itself, once the append-only assumption behind it turned out not to hold.
  • A provenance-checking tool whose own core git-history walk had been silently truncated by shallow clones since the day it was built — caught only by testing the checker against known-good data, not by reading its code.
